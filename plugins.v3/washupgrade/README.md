# 洗版自用 (WashUpgrade)

**评分洗版插件**：对目标订阅做洗版（发现更优画质/编码版本时重新下载）。提供两种模式，并支持详情页一键手动触发。

适用宿主：**MoviePilot v3.2.1+**。

## 两种洗版模式（配置项「洗版模式」）

- **原生最佳版本（默认，推荐）**：定时 / 手动对目标订阅触发 MoviePilot 原生的「最佳版本」搜索，评分规则、画质 / 特效目标、分集 / 全集处理**全部由宿主完成**（即你在 MP「洗版评分规则」页 + 订阅「最佳版本」里配好的规则）。插件只负责挑订阅、按周期触发，不重复造轮子。
- **自定义类别打分**：插件按你在配置页**勾选的类别**（分辨率 / 来源 / 视频编码 / 音频编码 / 画质特效 / 色深 / 帧率 / 字幕 / 文件格式，维度与 MP 一致）自行打分，搜索并下载更优版本，**覆盖 MP 原生规则**，做精细控制。

> 两种模式都复用 MoviePilot 已配置的 PT 站点作为资源来源（由宿主搜索 / 下载链负责）。

## 自定义类别模式说明

配置页的「② 自定义类别」分区在「洗版模式 = 自定义类别打分」时生效，样式参照 MP「洗版评分规则」页：

- **9 个维度**：每个维度一个开关（#1 分辨率 … #9 文件格式），关掉即忽略该维度。
- **类别多选**：每个维度点开下拉，勾选你需要的类别（如分辨率勾 8K / 4K / 1080P）。同一维度内**列表越靠前越优先**；不勾选的类别不会命中。无需填任何数字。
- **最低接受分辨率**：低于此分辨率的资源直接跳过（如设 4K，则 1080P 及以下不洗）。
- **排除关键词**：命中即跳过（如 `国配,德语`），逗号分隔。
- **优先关键词**：命中额外加分（如 `DIY,REMUX`），逗号分隔。
- **评分提升阈值**：新资源的评分需高于已下载最佳分该阈值，才真正下载（防止微小升级反复下载）。

打分逻辑：维度越靠前（#1→#9）权重越高；同一维度内，勾选列表里越靠前的类别得分越高；未启用的维度不参与。优先词额外加分。最终分值用于和「已下载最佳分」基线比较。

## 手动触发

插件详情页（「数据」页）顶部有一个 **「立即洗版一次（手动触发）」** 按钮：点击后立即按当前配置执行一次洗版（受「试运行」开关控制——开试运行则只记录不下载）。底层通过插件 API `POST /plugin/WashUpgrade/run` 触发，后台线程执行，不阻塞界面。

## 工作流程

1. 读取全部订阅。
2. 按配置过滤：仅保留「已开启最佳版本」的订阅（可放宽），并按范围（全部 / 仅电影 / 仅电视剧）筛选。
3. **跳过已完成洗版的订阅**（不再产生任何站点请求）。
4. 按模式执行：
   - 原生：逐个触发 `SubscribeChain().search(sids=(id,), manual=True)`；
   - 自定义：逐订阅搜索 → 分集/全集分流 → 维度打分 + 过滤 → 与当前版本比 → 下载更优版本（全集无条件优先）。
5. 每次洗完判断是否达到封顶条件（目标画质 / 洗满次数 / 洗到全集 / 连续无更优），达到则标记完成、从首页移除。
6. 试运行模式下只记录将执行的操作，不真正搜索 / 下载，也不会访问任何站点。
7. 实际执行时按「请求频率控制」三项放缓节奏：冷却跳过 → 分批取 N 个 → 逐个订阅、之间等待。

## 配置项

| 配置 | 说明 | 默认 |
| --- | --- | --- |
| 启用评分洗版 | 总开关（同时控制定时任务是否注册） | 关 |
| 洗版模式 | 原生最佳版本 / 自定义类别打分 | 原生 |
| 洗版范围 | 全部订阅 / 仅电影 / 仅电视剧 | 全部 |
| 仅对开启「最佳版本」的订阅洗版 | 收窄到明确要洗版的订阅（建议开） | 开 |
| 电视剧洗版方式 | 分集也洗 / 出全集后自动转全集 / 只等全集 / 只按分集洗 | 分集也洗 + 自动转全集 |
| 同一订阅最多洗几次 | 洗满即判定完成，不再检测（0 = 不限） | 2 |
| 洗到这个分辨率就算到顶 | 当前版本达到该分辨率后不再洗 | 4K |
| 洗到这个来源就算到顶 | 可选，一般不用设 | 不封顶 |
| 洗到「全集/整季」即视为完成 | 电视剧洗到全集后不再洗单集 | 开 |
| 连续几轮没找到更优就收工 | 避免无限检测；电视剧等全集阶段不适用（0 = 不放弃） | 3 |
| 完成的订阅从详情页移除 | 只显示还在洗的订阅 | 开 |
| 扫描周期 | Cron 表达式 | `0 4 * * *`（每天 4 点） |
| 试运行 | **只记录、不真正搜索 / 下载**，首次务必保持开 | 开 |
| 立即运行一次 | 保存配置后立刻按当前配置执行一次，执行完自动复位为关（不复位则重启会重复跑） | 关 |
| 每个订阅之间的间隔（秒） | 处理完一个订阅后等待多久再处理下一个（自动加 0~25% 随机抖动，避免固定节奏特征） | 60 |
| 每轮最多处理订阅数 | 一轮最多洗多少个订阅，其余下一轮从上次结束处继续轮转（0 = 不限） | 10 |
| 同一订阅冷却（小时） | 该订阅洗过一次后，这么多小时内再触发会直接跳过，不产生任何站点请求（0 = 不限） | 12 |
| 各维度「类别」（自定义模式） | 9 个维度各一个开关 + 类别多选框（如分辨率选 8K/4K/1080P），列表越靠前越优先 | 全部类别 |
| 最低接受分辨率（自定义模式） | 低于则跳过 | 不限 |
| 排除关键词（自定义模式） | 逗号分隔 | 空 |
| 优先关键词（自定义模式） | 命中加分，逗号分隔 | 空 |
| 评分提升阈值（自定义模式） | 超过基线该值才下载 | 0 |

## 详情页（海报一览）

插件详情页不再堆文字，而是一张张卡片：**左海报、右片名 + 当前版本 + 集数进度**，一眼就能看出每个订阅现在拿的是什么版本。

- 海报取自 MP 订阅里的 `poster` 字段；豆瓣图会自动走后端图片代理，没有海报的显示带首字的灰色占位块，不会破图。
- 「当前版本」= MP 下载记录里该订阅最近一次下载的种子名，带 5 分钟缓存，不会每次打开都查库。
- 集数进度 = `总集数 - 缺集数`，例如 `24/32 集`。
- 顶部保留「立即洗版一次」按钮，底部保留最近 8 条运行记录。
- **已洗版完成的订阅不再出现在列表里**，只显示还在洗的；列表底部一行「已完成洗版 N 个（已从列表移除）」，旁边有「重置完成状态」按钮，想重洗一键恢复。

## 电视剧：分集也洗，出全集后自动转全集

追更中的剧集，站点上会不断出现「单集」和后期才出现的「全集/整季包」。插件默认按这个顺序处理：

1. **追更期间洗分集**：站点没有全集时，按分集正常比画质。比如你库里是 1080P 的 EP05，站点有 2160P 的 EP05，就洗成 4K。
2. **全集一出现，立刻转全集**：只要站点出现全集/整季包（`全集`、`全32集`、`COMPLETE`、`SEASON PACK`），**无条件转洗全集**——不再拿全集的分数和单集比分（两者片名几乎一样，比分永远分不出高下）。
3. **洗到全集就收工**：洗完全集后该订阅标记为完成，不再检测、不再洗单集。反过来，如果库里已经是全集版本，插件**不会**用单集去覆盖它（防止把全集洗成单集）。

配置项「电视剧洗版方式」还能切到另外两种：

| 选项 | 行为 |
| --- | --- |
| 分集也洗，出全集后自动转全集（默认） | 上面三步 |
| 只等全集，分集不洗 | 分集一律跳过，只在出现全集时洗 |
| 只按分集洗，不区分全集 | 不区分单集/全集，纯粹按画质打分 |

> 原生模式不需要这个配置：`SubscribeChain` 触发的是 MP 自带的最佳版本逻辑，分集/全集由宿主处理。

## 洗到什么时候停（防止无限洗版）

不设上限的话，插件会一直反复检测、反复洗版——既浪费站点请求，也可能被判定为爬虫。下面任意一条满足，该订阅就判定「洗版完成」：

| 完成条件 | 说明 | 默认 |
| --- | --- | --- |
| 洗到目标画质 | 当前版本已达到「洗到这个分辨率」（4K） | 开 |
| 洗满次数 | 同一订阅累计洗满 N 次（默认 2 次：分集一次 + 全集一次） | 2 次 |
| 洗到全集 | 电视剧洗完全集/整季包 | 开 |
| 连续多轮无更优 | 连续 N 轮都找不到更高分的资源，判定已到顶 | 3 轮 |

标记完成后：

- **不再访问站点**：`wash()` 会在构建任务列表时跳过它，一次搜索请求都不发；
- **从详情页移除**：首页列表只留还在洗的订阅；
- **状态持久化**：记录存在插件数据里，重启 MoviePilot 不会丢；
- **可重置**：详情页底部「重置完成状态」按钮（API `POST plugin/WashUpgrade/reset_done`）清空记录，所有订阅重新参与。

> 两个例外，别被绕晕：
> 1. **电视剧等全集期间不会因为「连续多轮无更优」或「已达目标画质」而收工**——否则分集先洗到 4K 就停了，永远等不到自动转全集。这个阶段只由「洗满次数」和「洗到全集」结束。
> 2. 「已达目标画质」只在插件确实洗过（洗版次数 > 0）之后才算数，否则点「重置」会立刻又被判完成。

## 请求频率控制（防站点封禁）

一次洗版会为**每个订阅**向所有已配置 PT 站点发一轮搜索请求。订阅一多，短时间内的请求量很容易被站点判定为爬虫，导致临时封禁 / 拉黑。插件内置三道闸：

1. **订阅间隔**：每处理完一个订阅等待 N 秒（默认 60，实际会在 60~75 秒之间随机），把一次密集请求摊成一条缓慢的长链。
2. **分批轮转**：每轮最多处理 N 个订阅（默认 10），剩下的下一轮从上次结束处接着洗，不会总是只洗排在前面的那几个。
3. **订阅冷却**：同一个订阅洗过一次后，N 小时内再次触发直接跳过，不发出任何请求（默认 12 小时）。

`0` 表示关闭对应限制（间隔 0 = 不等待；每轮 0 = 不限量；冷却 0 = 不跳过）。

**经验值**：订阅 ≤ 20 个用默认（60 秒 / 每轮 10 个）即可；订阅 50+ 建议间隔调到 120~180 秒、每轮 5~10 个；如果站点已经警告过你，间隔先拉到 300 秒跑几天再降。

**双保险**：MoviePilot「站点管理」里每个站点还有自己的流控字段（`limit_interval` / `limit_count` / `limit_seconds`），建议一并设置，插件侧限流 + 站点侧限流两层叠加最稳。

> 原生模式也一样受这三道闸控制：插件已改为**逐个订阅触发**原生搜索（原来是整批一次性触发，节奏无法控制）。

## 日志 / 运行记录

- 写入宿主插件日志（`logs/plugins/washupgrade.log`，插件「查看日志」按钮里看）与**内存活动缓存**。
- 内存缓存在插件「数据」页（详情页）以「运行记录（最近 30 条）」展示，即使日志文件暂不可读也能看到运行轨迹。

自定义模式的运行记录按「当前版本 → 对比 → 是否洗版」三步叙述，例如：

```
《某电影》当前版本：某电影.2024.1080P.WEB-DL.AVC.AAC.CHS.MP4（评分 259）
《某电影》对比后发现更高版本：某电影.2024.2160P.UHD-BLURAY.REMUX.HEVC.DV.DTS-HD.MA7.1.CHS&CHT.MKV（评分 398）
《某电影》进行评分洗版：开始下载
```

「当前版本」取自 MP 下载记录里该订阅最近一次下载的种子名；取不到时显示「未记录」。

## 使用步骤

1. 安装插件，打开「启用评分洗版」。若用「原生」模式，先在 MP 里配好「洗版评分规则」并给订阅开「最佳版本」、设画质目标；若用「自定义类别」模式，在配置页勾选各维度需要的类别与过滤项。
2. 保持「试运行」为开，保存，点详情页「立即洗版一次」或等定时周期，打开「数据」页确认记录符合预期。
3. 确认无误后关闭「试运行」，才会真正搜索 / 下载。

## 已知限制

- **原生模式**：洗版效果完全取决于 MP 里的评分规则与订阅最佳版本目标；插件不评分、不筛选。
- **自定义模式**：打分基于资源标题文本匹配，非常规命名可能漏判某个维度（只影响该维度分，不影响其他）；电视剧按剧名搜索，单集/全集靠标题里的「全集 / 全N集 / COMPLETE / SEASON PACK」等字样识别，命名太特殊的全集包可能识别不到（此时会当成分集处理）。基线优先用「下载记录里的当前版本标题」实时推算，取不到时用内存记录，再兜底为宿主去重。
- **洗版完成状态**按「类型 + 片名 + 年份」记录；如果你手动换了版本想重新洗，请点详情页「重置完成状态」。
- 触发节奏与并发受宿主订阅搜索队列控制。

## 发布 / 加载

1. 推到 GitHub 仓库的 `main` 分支（本仓库：`moviepilot-v3-plugins`）。
2. 在 MoviePilot 配置项 `PLUGIN_MARKET` 填入仓库地址（多个用逗号分隔）。
3. 插件市场即可发现并安装。

> 发布前确认 `__init__.py` 的 `plugin_version`、`package.v3.json` 的 `version`、`history` 顶部版本三者一致。
> 把 `WashUpgrade`、作者 `your-name` 与链接替换为你自己的标识（目录名需为类名小写 `washupgrade`）。
