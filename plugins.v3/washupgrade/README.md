# 洗版自用 (WashUpgrade)

**评分洗版插件**：对目标订阅做洗版（发现更优画质/编码版本时重新下载）。提供两种模式，并支持详情页一键手动触发。

适用宿主：**MoviePilot v3.2.1+**。

## 两种洗版模式（配置项「洗版模式」）

- **原生最佳版本（默认，推荐）**：定时 / 手动对目标订阅触发 MoviePilot 原生的「最佳版本」搜索，评分规则、画质 / 特效目标、分集 / 全集处理**全部由宿主完成**（即你在 MP「洗版评分规则」页 + 订阅「最佳版本」里配好的规则）。插件只负责挑订阅、按周期触发，不重复造轮子。
- **自定义类别打分**：插件按你在配置页**勾选的类别**（分辨率 / 来源 / 视频编码 / 音频编码 / 画质特效 / 色深 / 帧率 / 字幕 / 文件格式，维度与 MP 一致）自行打分，搜索并下载更优版本，**覆盖 MP 原生规则**，做精细控制。

> 两种模式都复用 MoviePilot 已配置的 PT 站点作为资源来源（由宿主搜索 / 下载链负责）。

## 自定义类别模式说明

配置页的「② 自定义类别」分区在「洗版模式 = 自定义类别打分」时生效，样式参照 MP「洗版评分规则」页：

- **9 个维度**：每个维度一个开关（#1 分辨率 … #9 文件格式），关掉即忽略该维度。
- **类别多选**：每个维度点开下拉，勾选你需要的类别（如分辨率勾 8K / 4K / 1080P）。同一维度内**列表越靠前越优先**；不勾选的类别不会命中。无需填任何数字。
- **最低接受分辨率**：低于此分辨率的资源直接跳过（如设 4K，则 1080P 及以下不洗）。
- **排除关键词**：命中即跳过（如 `国配,德语`），逗号分隔。
- **优先关键词**：命中额外加分（如 `DIY,REMUX`），逗号分隔。
- **评分提升阈值**：新资源的评分需高于已下载最佳分该阈值，才真正下载（防止微小升级反复下载）。

打分逻辑：维度越靠前（#1→#9）权重越高；同一维度内，勾选列表里越靠前的类别得分越高；未启用的维度不参与。优先词额外加分。最终分值用于和「已下载最佳分」基线比较。

## 手动触发

插件详情页（「数据」页）顶部有一个 **「立即洗版一次（手动触发）」** 按钮：点击后立即按当前配置执行一次洗版（受「试运行」开关控制——开试运行则只记录不下载）。底层通过插件 API `POST /plugin/WashUpgrade/run` 触发，后台线程执行，不阻塞界面。

## 工作流程

1. 读取全部订阅。
2. 按配置过滤：仅保留「已开启最佳版本」的订阅（可放宽），并按范围（全部 / 仅电影 / 仅电视剧）筛选。
3. **跳过已完成洗版的订阅**（不再产生任何站点请求）。
4. 按模式执行：
   - 原生：逐个触发 `SubscribeChain().search(sids=(id,), manual=True)`；
   - 自定义：逐订阅搜索 → 分集/全集分流 → 维度打分 + 过滤 → 与当前版本比 → 下载更优版本（全集无条件优先）。
5. 每次洗完判断是否达到封顶条件（目标画质 / 洗满次数 / 洗到全集 / 连续无更优），达到则标记完成、从首页移除。
6. 试运行模式下只记录将执行的操作，不真正搜索 / 下载，也不会访问任何站点。
7. 实际执行时按「请求频率控制」三项放缓节奏：冷却跳过 → 分批取 N 个 → 逐个订阅、之间等待。

## 详情页（海报一览）

插件详情页不再堆文字，而是一张张卡片：**左海报、右片名 + 当前版本 + 集数进度**，一眼就能看出每个订阅现在拿的是什么版本。

- 海报取自 MP 订阅里的 `poster` 字段；豆瓣图会自动走后端图片代理，没有海报的显示带首字的灰色占位块，不会破图。
- 「当前版本」= MP 下载记录里该订阅最近一次下载的种子名，带 5 分钟缓存，不会每次打开都查库。
- 集数进度 = `总集数 - 缺集数`，例如 `24/32 集`。
- 顶部保留「立即洗版一次」按钮，底部保留最近 8 条运行记录。
- **已洗版完成的订阅不再出现在列表里**，只显示还在洗的；列表底部一行「已完成洗版 N 个（已从列表移除）」，旁边有「重置完成状态」按钮，想重洗一键恢复。

## 电视剧：分集也洗，出全集后自动转全集

追更中的剧集，站点上会不断出现「单集」和后期才出现的「全集/整季包」。插件默认按这个顺序处理：

1. **追更期间洗分集**：站点没有全集时，按分集正常比画质。比如你库里是 1080P 的 EP05，站点有 2160P 的 EP05，就洗成 4K。
2. **全集一出现就转全集，但必须过画质关**：站点出现全集/整季包（`全集`、`全32集`、`COMPLETE`、`SEASON PACK`）时不再比分（全集与单集片名几乎一样，比分永远分不出高下），改为逐维比较画质（分辨率 → 来源 → 视频编码 → 画质特效 → 色深）。
   - 全集画质 **≥** 当前版本 → 立刻转全集；
   - 全集画质 **<** 当前版本（例如站点只发 1080P 全集，而你库里是 4K 分集）→ **不转**，日志写「发现全集资源但画质低于当前版本…继续等更好的全集」。
3. **洗到全集就收工**：洗完全集后该订阅标记为完成，不再检测、不再洗单集。反过来，如果库里已经是全集版本，插件**不会**用单集去覆盖它（防止把全集洗成单集）。

配置项「电视剧洗版方式」还能切到另外两种：

| 选项 | 行为 |
| --- | --- |
| 分集也洗，出全集后自动转全集（默认） | 上面三步 |
| 只等全集，分集不洗 | 分集一律跳过，只在出现全集时洗 |
| 只按分集洗，不区分全集 | 不区分单集/全集，纯粹按画质打分 |

> 原生模式不需要这个配置：`SubscribeChain` 触发的是 MP 自带的最佳版本逻辑，分集/全集由宿主处理。

## 洗到什么时候停（防止无限洗版）

不设上限的话，插件会一直反复检测、反复洗版——既浪费站点请求，也可能被判定为爬虫。下面任意一条满足，该订阅就判定「洗版完成」：

| 完成条件 | 说明 | 默认 |
| --- | --- | --- |
| 洗到封顶档位 | 当前版本已达到你设的所有封顶档位（默认只看分辨率 4K；可再加来源、画质特效等，全都要达到） | 4K |
| 洗满次数 | 同一订阅累计洗满 N 次（默认 2 次：分集一次 + 全集一次） | 2 次 |
| 洗到全集 | 电视剧洗完全集/整季包，**且该全集达到了封顶档位**（1080P 全集在目标 4K 时不算完成） | 开 |
| 连续多轮无更优 | 连续 N 轮都找不到更高分的资源，判定已到顶 | 3 轮 |

标记完成后：

- **不再访问站点**：`wash()` 会在构建任务列表时跳过它，一次搜索请求都不发；
- **从详情页移除**：首页列表只留还在洗的订阅；
- **状态持久化**：记录存在插件数据里，重启 MoviePilot 不会丢；
- **可重置**：详情页底部「重置完成状态」按钮（API `POST plugin/WashUpgrade/reset_done`）清空记录，所有订阅重新参与。

**怎么设封顶档位**：配置页「封顶 · #n 维度」共 9 项，每项都能选「不限」或具体档位。设了档位的维度取「与」——全部达到才停；没设的维度不参与判断。常见几档：

| 目标 | 怎么设 |
| --- | --- |
| 洗到 4K 就停（默认） | 只设 分辨率 = 4K，其余不限 |
| 4K + 蓝光以上才停 | 分辨率 = 4K，来源 = BLURAY |
| 只要 4K 的 HDR | 分辨率 = 4K，画质特效 = HDR10（注意：SDR 排在其后，达不到会一直等） |
| 永不封顶（只靠次数/放弃兜底） | 9 项全设「不限」 |

> 两个例外，别被绕晕：
> 1. **电视剧等全集期间不会因为「连续多轮无更优」或「已达目标画质」而收工**——否则分集先洗到 4K 就停了，永远等不到自动转全集。这个阶段只由「洗满次数」和「洗到全集」结束。
> 2. 「已达目标画质」只在插件确实洗过（洗版次数 > 0）之后才算数，否则点「重置」会立刻又被判完成。
> 3. 电视剧选「分集也洗 / 只等全集」时，在洗到全集之前**不会**因为「连续多轮无更优」而放弃——
>    否则永远等不到全集。这个阶段只由「洗满次数」和「洗到全集」结束；扫描仍受请求间隔 / 冷却 / 每轮上限约束。

## 自动化与运行节奏（一天跑几轮）

插件**是全自动的**，但「点一次按钮」只等于「额外补跑一轮」，不会自己一直循环。真正的自动化来自定时任务：

- 定时任务由配置项「扫描周期」控制，默认 `0 4 * * *` = **每天 04:00 跑 1 轮**；
- 插件启用后定时任务才会注册（未启用只能在详情页手动点）；
- 一轮跑完就结束，下一轮等下一个定时点。

所以「一天跑几轮」= 你的 cron 写了几个触发点。常见配置：

| 想要 | 扫描周期 | 冷却建议 | 说明 |
| --- | --- | --- | --- |
| 一天 1 轮（默认，省心） | `0 4 * * *` | 12 小时 | 适合大多数人的库，新资源一天内基本都能覆盖 |
| 一天 2 轮 | `0 4,16 * * *` | 8 小时 | 追更剧想早点拿到全集时用 |
| 一天 3 轮 | `0 6,14,22 * * *` | 6 小时 | 站点请求量约为 3 倍，注意站点承受度 |
| 每 2 小时（激进） | `0 */2 * * *` | 1 小时 | 只建议订阅很少、站点很宽松时用 |

### 100 个订阅怎么配（一天全部扫到）

先算账：**单轮耗时 = 订阅数 × 每个订阅之间的间隔**。

| 订阅数 | 间隔 | 单轮耗时 | 建议周期 |
| --- | --- | --- | --- |
| 100 | 60 秒 | 100 分钟 | 一天 1 轮 `0 4 * * *` 就够 |
| 100 | 30 秒 | 50 分钟 | 一天 2 轮 `0 4,16 * * *`，冷却 8 小时 |
| 100 | 15 秒 | 25 分钟 | 一天 3 轮，冷却 6 小时（站点要宽松） |

**前提：「单次运行最多处理订阅数」必须是 0。** 如果这里是 10，一天跑多少轮都只能扫到 10 个。

> ⚠️ 升级过插件的老用户注意：这个值**存在你自己的配置里**，升级不会自动改。如果详情页出现「当前只处理 10 个，还有 90 个订阅本次不会处理」，点下面的「改成一次跑完全部订阅（设为 0）」按钮即可，不用手动找配置项。

运行日志里可以直接核对覆盖率：

```
订阅总数 100 个，本轮待洗 100 个
…
自定义类别打分洗版完成，处理 100 个订阅（本轮已覆盖全部待洗订阅）
```

**关键：冷却时间必须小于周期间隔**，否则多出来的轮次会被冷却全部跳过——等于白跑还多打了一堆站点请求。详情页会自动检查并提示：

- `冷却 12 小时 ≥ 周期间隔 8 小时：每天 3 轮里多出来的轮次会被全部跳过…`；
- `单轮预计 240 分钟，超过周期间隔 120 分钟：上一轮还没跑完下次又到点（重叠的触发会被跳过）`。

详情页状态行会直接显示 `周期 0 4 * * *（每天约 1 次）· … · 预计单轮 ~30 分钟`，不用自己算。

**单轮耗时怎么估**：`待洗订阅数 × 每个订阅之间的间隔`。30 个订阅、间隔 60 秒 ≈ 30 分钟；120 个订阅、间隔 120 秒 ≈ 240 分钟（4 小时）。单轮耗时超过周期间隔就会出现「跑不完」，此时要么调小间隔，要么减少单次数量，要么降低轮次。

> 注意：**冷却记录、分批续接点、基线标题现在都会持久化**，MoviePilot 重启后不会把全部订阅重扫一遍。「已洗版完成」的记录同样持久化。详见下面「生命周期与状态持久化」。

## 请求频率控制（防站点封禁）

一次洗版会为**每个订阅**向所有已配置 PT 站点发一轮搜索请求。订阅一多，短时间内的请求量很容易被站点判定为爬虫，导致临时封禁 / 拉黑。插件内置三道闸：

1. **订阅间隔**：每处理完一个订阅等待 N 秒（默认 60，实际会在 60~75 秒之间随机），把一次密集请求摊成一条缓慢的长链。
2. **单次上限**（可选，默认关闭）：如果填了数值，一次运行只处理 N 个订阅，剩下的下次从「上次最后一个」之后接着洗。默认 0 = 一次跑完，靠上面的间隔控制节奏就够了。
3. **订阅冷却**：同一个订阅洗过一次后，N 小时内再次触发直接跳过，不发出任何请求（默认 12 小时）。

`0` 表示关闭对应限制（间隔 0 = 不等待；每轮 0 = 不限量；冷却 0 = 不跳过）。

**经验值**：订阅 ≤ 30 个用默认（60 秒、不限量）即可，一次跑完大概半小时；订阅 50+ 建议间隔调到 120~180 秒；如果站点已经警告过你，间隔先拉到 300 秒跑几天再降，同时把「单次运行最多处理订阅数」设成 10~20 分批跑。

**双保险**：MoviePilot「站点管理」里每个站点还有自己的流控字段（`limit_interval` / `limit_count` / `limit_seconds`），建议一并设置，插件侧限流 + 站点侧限流两层叠加最稳。

> 原生模式也一样受这三道闸控制：插件已改为**逐个订阅触发**原生搜索（原来是整批一次性触发，节奏无法控制）。

## 通知（Telegram / 微信 / Bark）

洗版结果通过 **MoviePilot 自己的通知渠道**推送，插件不直连 Telegram——只要你在 MP「设置 → 消息通知」里配好了 Telegram 机器人，这里开着就会收到。

三种模式（配置项「通知内容」）：

| 模式 | 收到什么 | 适合 |
| --- | --- | --- |
| 每次运行汇总（默认） | 一条消息：处理了几个、洗了哪几个（片名 → 新版本）、哪几个洗到顶了 | 日常使用，一天最多几条 |
| 每洗一次明细 | 每洗一次一条，含**旧版本 → 新版本 + 评分变化**；洗到顶再一条 | 想盯细节 / 排查为什么洗 |
| 只在洗到顶时 | 只有订阅完成洗版时才发 | 只想被通知「这部搞定了」 |

示例（汇总）：

```
洗版报告
处理 5 个订阅，洗版 2 个，完成 1 个
· 深渊无间 → 深渊无间.2026.全32集.2160P.WEB-DL.HEVC.CHS.mkv（全集）
· 某电影 → 某电影.2025.2160P.UHD-BLURAY.REMUX.HEVC.CHS.mkv
已洗到顶：现在不是出轨的问题
```

示例（明细）：

```
洗版：深渊无间
《深渊无间》已洗版（全集）
旧：深渊无间.2026.EP05.1080P.WEB-DL.AVC.CHS.mp4
新：深渊无间.2026.全32集.2160P.WEB-DL.HEVC.CHS.mkv
评分：259 → 313
```

几条行为约定：

- **试运行不发通知**（避免调试时刷屏）。
- **一次运行什么都没洗、也没标记完成时不发**，不会每天空报。
- **通知失败不影响洗版**：发不出去只写一行日志（`发送通知失败（不影响洗版）：…`），下载照常进行。
- 原生模式也会通知，内容写「已触发原生最佳版本搜索」（具体版本由 MP 自己的通知负责）。

## 日志 / 运行记录

- 写入宿主插件日志（`logs/plugins/washupgrade.log`，插件「查看日志」按钮里看）与**内存活动缓存**。
- 内存缓存在插件「数据」页（详情页）以「运行记录（最近 30 条）」展示，即使日志文件暂不可读也能看到运行轨迹。

自定义模式的运行记录按「当前版本 → 对比 → 是否洗版」三步叙述，例如：

```
《某电影》当前版本：某电影.2024.1080P.WEB-DL.AVC.AAC.CHS.MP4（评分 259）
《某电影》对比后发现更高版本：某电影.2024.2160P.UHD-BLURAY.REMUX.HEVC.DV.DTS-HD.MA7.1.CHS&CHT.MKV（评分 398）
《某电影》进行评分洗版：开始下载
```

「当前版本」取自 MP 下载记录里该订阅最近一次下载的种子名；取不到时显示「未记录」。

## 常见疑问

**Q：点了一次「立即洗版一次」，日志只有十来条就没了，是没跑吗？**

先看「数据」页顶部的状态和「上次运行」那行：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 「上次运行」写着「还剩 N 个未处理」 | 你填了「单次运行最多处理订阅数」，本次只跑了一批 | 再点一次「立即洗版一次」会接着洗；或把该值改成 0 |
| 顶部显示「正在洗版中」 | 正在后台跑，每处理一个订阅才输出一批日志 | 等它跑完；期间别重复点 |
| 「本轮全部订阅都在冷却期内，跳过」 | 同一订阅 12 小时内洗过 | 正常，等冷却结束；或把冷却改成 0 |
| 「已完成洗版：N 个订阅已到顶，本轮跳过」 | 这些订阅已经洗到封顶档位 | 正常；想重洗点「重置完成状态」 |
| 什么都没变，也没有新记录 | 定时任务还没到点（默认每天 04:00），或者插件是「未启用」状态 | 看顶部状态；手动点按钮触发一次 |

**Q：MP 的「插件日志」页看不到内容？**

插件的运行轨迹以「数据」页的**运行记录**为准（现在显示最近 30 条，并标注总条数）。MP 自带日志页对 `plugins.v3` 目录下的插件不一定能正确分文件，那个页面看不到不代表插件没跑。

**Q：为什么一次跑这么久？**

每处理一个订阅要等 60 秒左右是故意的——短时间内连续请求同一个站点容易被判定为爬虫。50 个订阅跑半小时是正常节奏，后台执行不影响你用 MP。

## 生命周期与状态持久化

### 停用 / 重载插件时会发生什么

- 宿主停用插件会调用 `stop_service()`，插件只**置一个停止标志**，不强行杀线程：
  正在跑的循环会在**当前订阅处理完后**自行退出（日志：`插件已停用，本轮提前结束（已处理 2/5 个）`），
  不会把「已提交下载」的动作割断在半途。
- 重新启用时这个标志会自动清除；定时任务由宿主统一管理（每次配置变更会先移除旧的再重建），插件不需要自己取消。
- 「保存配置后立刻运行一次」改为**延迟 8 秒**再执行，并在真正开跑前二次确认插件仍处于启用状态——
  避免宿主刚写完配置、各链尚未就绪时开跑。

### 哪些状态会持久化

存在 MoviePilot 的插件数据表 `plugindata`（数据库事务内原子写入，不是写文件，所以不存在文件半写损坏的问题）：

| 状态 | 作用 | 重启后 |
| --- | --- | --- |
| 已完成洗版记录 | 到顶的订阅不再检测 | 保留 |
| 同一订阅的冷却时间 | 冷却期内跳过 | 保留（只保留 7 天内） |
| 分批续接点 | 下次从哪个订阅之后继续 | 保留 |
| 上次下载的版本标题 | 下载历史取不到时的基线兜底 | 保留 |

> 读取侧做了类型容错：如果持久化数据格式异常，会记一行 `已完成的洗版记录格式异常，已按空处理` 并继续跑，不会让插件启动失败。
> 最坏的后果只是「重新扫一遍」——不会导致重复下载，因为每次都会先和「当前版本」比对分数。

## 使用步骤

1. 安装插件，打开「启用评分洗版」。若用「原生」模式，先在 MP 里配好「洗版评分规则」并给订阅开「最佳版本」、设画质目标；若用「自定义类别」模式，在配置页勾选各维度需要的类别与过滤项。
2. 保持「试运行」为开，保存，点详情页「立即洗版一次」或等定时周期，打开「数据」页确认记录符合预期。
3. 确认无误后关闭「试运行」，才会真正搜索 / 下载。

## 已知限制

- **原生模式**：洗版效果完全取决于 MP 里的评分规则与订阅最佳版本目标；插件不评分、不筛选。
- **自定义模式**：打分基于资源标题文本匹配，非常规命名可能漏判某个维度（只影响该维度分，不影响其他）；电视剧按剧名搜索，单集/全集靠标题里的「全集 / 全N集 / COMPLETE / SEASON PACK」等字样识别，命名太特殊的全集包可能识别不到（此时会当成分集处理）。基线优先用「下载记录里的当前版本标题」实时推算，取不到时用持久化的上次下载标题，再兜底为宿主去重。
- **洗版完成状态**按「类型 + 片名 + 年份」记录；如果你手动换了版本想重新洗，请点详情页「重置完成状态」。
- 触发节奏与并发受宿主订阅搜索队列控制。
